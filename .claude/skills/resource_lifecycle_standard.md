# 全域資源調度與交互規範 (Resource Lifecycle Standard)

## 1. 核心治理架構
本專案嚴禁任何套件（Package / Module）私自、獨佔或常駐硬體資源。所有套件必須透過統一的中央資源協調器（Resource Manager）進行動態申請、生命週期回報與被動驅逐。

## 2. 資源生命週期四階段
所有涉及高負載運算、大型數據載入（如 Pandas/Numpy 矩陣）或模型推論（如 PyTorch/Transformers/Ollama）的組件，必須嚴格遵守以下四個生命週期狀態：

### A. Initialized (已初始化)
- **定義**：物件已實例化，但尚未載入任何高耗能數據或模型。
- **規則**：嚴禁在模組頂層（Top-level scope）、全域變數或類別的 `__init__` 建構子中，執行實體檔案載入、GPU 移轉（.cuda() / .to()）或大數據讀取。

### B. Acquired (已配置)
- **定義**：任務執行前，組件已向中央管理器申報預估硬體開銷，並獲得配置許可。
- **規則**：必須在確認許可後，才可動態觸發模型或數據的載入程序。

### C. Executing (執行中)
- **定義**：運算進行中。
- **規則**：限縮高耗能物件的生存時間（Time-to-Live），非必要不留存中間狀態。

### D. Released (已釋放)
- **定義**：運算結束或被動觸發驅逐，資源全數歸還。
- **規則**：任務結束或收到管理器驅逐指令時，必須無條件解除物件引用（引用計數歸零），顯式驅動垃圾回收機制與顯示卡記憶體快取清理，並向管理器回報釋放。

## 3. 資源控制實作辦法

### 【主體記憶體 RAM 控制辦法】
- **分塊策略**：凡讀取大型磁碟檔案（如 CSV, Parquet, JSON），必須採用分塊（Chunking）或迭代產生器（Generator）模式，嚴禁一次性讀入全量數據。
- **顯式清理**：函數內部產生的暫存 Dataframe 或大型矩陣，在失去業務用途後，必須立即使用變數銷毀手段，並強制呼叫系統級垃圾回收。

### 【顯示卡記憶體 VRAM 控制辦法】
- **禁止常駐**：所有模型組件預設不常駐於 VRAM。必須包裹於內建的上下文管理器（Context Manager）或顯式的開啟/關閉生命週期函數中。
- **釋放鏈結**：模型移出 VRAM 時，必須完整執行「解除指標 -> 清空 CUDA 快取 -> 強制系統 GC」的標準釋放鏈。
- **被動驅逐機制 (Eviction)**：所有模型組件必須對外暴露一個無條件的驅逐介面。當中央管理器因全域資源不足發出警告時，不論組件目前是否處於閒置，皆須能被外部強制降級（Offload）至 CPU 或磁碟，釋放 VRAM。
