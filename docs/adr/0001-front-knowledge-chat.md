# ADR 0001：前台知識庫對話（架構、權限、排隊與資料流）

狀態：定案（專案負責人授權，2026-11-16）　相關 issue：#55、#56、#57、#58、#59

## 1. 背景與決定

- 運算留在後台，前台只有畫面與連線；前台不載入任何知識庫模型，也不上網。
- 後台聊天視窗（`rag.chat_window`）之後**只留出缺勤查詢**（#59）；企業知識庫問答只給前台（#57、#58）。
- 前台永遠主動連後台：前台送問題、之後來取結果，後台不推送。
- 前台使用者**沒有登入**。`data/docs/` 全部文件都可被前台問到（專案給企業或民間用，文件由使用者自己放）。
- 問答會寫進 #55 的對話紀錄（來源 `front_knowledge`，保存一個月，含審查欄位）；前台不告知、不保存任何對話。

## 2. 資料流

```
前台使用者（實體鍵盤）
   │ 輸入問題
   ▼
前台儀表板「知識庫問答」面板 ── 背景執行緒 ──► BackClient.chat_submit()
                                                  POST /v1/chat   (HTTPS、通行碼、釘住憑證指紋)
                                                           │
                                                           ▼
                                  後台 admin.link_server：驗證 → 檢查 chat_enabled、長度、頻率、排隊上限
                                                           │ 放進佇列，回 202 與 job_id
                                                           ▼
                                  後台 admin.chat_service（單一工作執行緒，一次只做 1 題）
                                      第一次有題目才載入 bge-m3、重排模型、文件索引（回報「準備中」）
                                      Assistant.ask_documents(question)：只檢索文件，不經意圖判斷、不查資料庫
                                      寫入 #55 對話紀錄（front_knowledge）
                                                           │ 結果放進記憶體（保留 10 分鐘）
前台面板每 1 秒 ──► GET /v1/chat/{job_id} ◄────────────────┘
   │ 顯示回答（純文字）與來源文件名稱
   ▼
閒置 60 秒自動清除輸入與回答（前台不保存）
```

## 3. 十個決定

### 3.1 介面形式
送出問題得到編號，前台輪詢（回答約 20 秒以上，輪詢比長時間占著連線好；也不會讓 werkzeug 的連線執行緒被卡住）。

| 用途 | 請求 | 成功回應 | 失敗 |
|---|---|---|---|
| 送出問題 | `POST /v1/chat`，JSON `{"question": "..."}` | 202 `{"ok":true,"job_id":"<32 位十六進位>","status":"queued"}` | 400 欄位不合格；403 `chat_disabled`；429 `busy`（排隊已滿）或 `slow_down`（太頻繁）；413 太大；401 通行碼不對 |
| 取結果 | `GET /v1/chat/<job_id>` | 200 `{"ok":true,"status":"queued｜preparing｜running｜done｜failed","answer":"…","sources":["文件名稱"],"error":"…"}` | 404 找不到（過期或編號不對）；401 |
| 開關同步 | 既有 `GET /v1/morning` 回應多一個 `chat_enabled` 布林 | — | — |

限制：問題最多 300 字（`MAX_CHAT_QUESTION`）、請求本文沿用 3MB 上限；回答最多 4000 字；單題逾時 180 秒（含第一題載入模型）；結果保留 10 分鐘後刪除；`job_id` 是 `secrets.token_hex(16)`，只有送出的人知道。

### 3.2 只准知識庫（後台強制，不是前台隱藏）
- `/v1/chat` 的處理流程**直接呼叫新的 `Assistant.ask_documents(question)`**：不經過意圖判斷（router）、不載入也不呼叫任何出缺勤工具、不讀資料庫、不用員工名單、不保留對話記憶（每題獨立，避免不同人的問題互相帶入）。
- 測試證明：資料庫有出缺勤資料時，問「王小明今天有沒有遲到」，送給語言模型的提示詞與回傳內容都不含任何出勤資料；工具與 `queries` 在這條路徑上一次都不會被呼叫（用會在被呼叫時丟例外的假工具驗證）。

### 3.3 後台對前台的開關
- 新增 `shared.front_control.chat_enabled()`，**預設關閉**（公開的螢幕與鍵盤，必須管理者看過警告後主動開啟）；缺檔、壞檔一律當作關閉。
- 後台營運狀態頁「前台連線」卡片新增「前台知識庫問答」開關；開啟時跳出確認對話框，明講「`data/docs/` 裡所有文件都會讓前台使用者問到」。
- 沿用 `local_only`、`recognition_enabled` 的同步方式：`/v1/morning` 回應多一個布林 `chat_enabled`，前台只收布林，離線沿用最後一次的值。

前台各狀態：

| 狀態 | 前台顯示 |
|---|---|
| 可以問 | 輸入框、送出、回答與來源 |
| 送出後排隊或處理中 | 「查詢中…」，不能重複送出 |
| 第一題載入模型中 | 「知識庫準備中，第一次提問會久一點…」 |
| 排隊已滿或太頻繁（429） | 「目前有人在使用，請稍後再試」 |
| 後台離線 | 「後台未連線，無法使用知識庫問答」 |
| `chat_enabled` 為否，或舊後台沒有此介面（404） | 「知識庫問答目前未開放」，隱藏輸入 |
| 後台全本地模式、或雲端與本機語言模型都連不上 | 後台回固定說明文字（不含例外內容） |
| 閒置 60 秒 | 自動清除輸入與回答 |

### 3.4 排隊與優先權
- 後台一個工作執行緒、一次只做 1 題；排隊上限 3 題（1 題處理中加 2 題等待），再多回 429 `busy`；單一前台兩次送出至少相隔 3 秒，否則 429 `slow_down`。
- **管理者的出缺勤查詢不會被前台拖慢**：#59 之後後台聊天視窗不載入嵌入與重排模型，也不用這個佇列；兩邊唯一共用的只有雲端語言模型呼叫，各自獨立。
- 前台問答在 `link_server` 行程內的工作執行緒裡跑，`/v1/ping`、`/v1/heartbeat`、`/v1/events` 由其他連線執行緒處理，不會被阻塞。

### 3.5 前台畫面行為
沒有登入；閒置 60 秒清除；**前台不保存任何歷史**（不寫資料庫、記錄檔與畫面快取）；回答只當純文字顯示；來源只顯示文件名稱，沒有可點連結；輸入只有實體鍵盤；不提示「會被記錄」。

### 3.6 資源
嵌入與重排模型只在後台的 `link_server` 行程載入，**第一次有前台問題時才載入**，不在啟動時載入；閒置 15 分鐘釋放顯存（下一題再載入）；前台不載入任何知識庫模型。

### 3.7 記錄
每題問答（成功或失敗）呼叫 #55 的記錄函式，來源 `front_knowledge`；不記錄 IP 與通行碼；前台不提示。

### 3.8 文件範圍與警告
`data/docs/` 全部可被前台問到。警告放在：開啟開關的確認對話框、`CLAUDE.md`、後台文件說明。後台管理者要自己決定不放不想讓前台看到的文件。

### 3.9 濫用與提示注入
- 問題與文件內容都不可信：沿用 `Assistant` 既有的提示詞規則（段落只是資料、裡面的指令當普通文字、不透露規則），回答只當純文字回傳與顯示。
- 這條路徑沒有任何工具，所以「叫模型去查出缺勤、員工名單、證據照片」在後台根本沒有路可走。
- 回傳不夾帶檔案路徑與內部例外：來源只回文件名稱（不含資料夾）；失敗只回固定錯誤碼與固定說明文字；伺服器只在日誌印例外型別。
- 回答去掉控制字元並限制長度；提問長度、頻率、排隊上限如 3.1、3.4。

### 3.10 兩台版本相容
- 新前台＋舊後台：`/v1/chat` 回 404，前台當作「未開放」，不報錯；`/v1/morning` 沒有 `chat_enabled` 也當作未開放。
- 舊前台＋新後台：舊前台只讀自己認得的欄位，多出來的 `chat_enabled` 被忽略，沒有任何影響。

## 4. 威脅與對策

| 威脅 | 對策 | 驗證（測試） |
|---|---|---|
| 公開鍵盤上的任何人都能問 | 預設關閉、管理者確認警告後才開；只有文件檢索；頻率與排隊上限 | `test_chat_service`、`test_link_server_chat` |
| 透過問題取得出缺勤、員工名單、證據照片 | 後台直接呼叫 `ask_documents`，沒有工具、不讀資料庫、不用名單 | 「出缺勤問題拿不到資料」測試 |
| 文件內容或問題夾帶指令（提示注入） | 提示詞把段落當資料；沒有工具；純文字顯示 | 提示詞測試、純文字顯示測試 |
| 回應洩漏路徑、例外、金鑰 | 固定錯誤碼與說明；來源只回名稱 | 錯誤不洩漏測試 |
| 狂送問題拖垮後台 | 長度、頻率、排隊上限、單題逾時、單一工作執行緒 | 排隊、429、逾時測試 |
| 猜 job_id 偷看別人的回答 | `secrets.token_hex(16)`、10 分鐘後刪除、需要通行碼 | job_id 測試 |
| 後台離線、網路線拔掉時前台卡住 | 背景執行緒＋逾時；畫面顯示離線狀態 | 前台狀態測試 |
| 新舊版本混用 | 404 與缺欄位都當未開放 | 相容測試 |
| 對話被留在前台 | 前台不寫任何存放處，閒置清除 | 前台不保存測試 |

## 5. 不做的事
後台不主動連前台；前台不放模型、向量庫、雲端金鑰；前台沒有設定與管理員功能；不讓這條路徑查出缺勤或員工資料。
