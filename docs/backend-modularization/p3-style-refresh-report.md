# P3 追加修改：卡片牆風格更新

你回饋第一版卡片牆「有點土」，這輪針對**視覺風格**整個換掉，但沒有照抄 Cubi 截圖——配色、卡片比例、圖示畫法都是自己抓的，借用的是「淺色底＋卡片式模組＋頂部時鐘＋底部系統狀態」這個組織方式，不是複製畫面。

## 這輪改了什麼

1. **主題從深色（darkly）換成淺色（cosmo）**：`__main__` 那行 `ttk.Window(themename=...)` 改掉。第一版用深色主題配陽春的外框按鈕，對比度差、看起來悶；淺色主題的藍色主色跟白底，質感提升最明顯的一步。

2. **卡片從「純色 Frame + 文字」改成「Canvas 手繪圓角矩形」**：Tkinter 原生元件沒有圓角，這裡用畫布手畫圓角矩形（平滑多邊形近似），卡片左上角多了一個色塊圓形圖示徽章，卡片底色是用該模組的主題色（綠/藍/黃/灰）往白色混出來的淡色調，滑鼠移上去會變成更深一點的同色系混色，移開恢復——整張卡片都能點擊，跟第一版行為一致，只是外觀從「扁平色塊」變成「圓角浮動卡片」。

3. **新增頂部標題列**：左邊品牌＋副標題，右邊是即時時鐘（每秒更新）＋日期，中間一條分隔線，呼應 Cubi 截圖裡「系統本身有自我監控意識」的設計語言，但擺放位置、字型跟截圖的管理員下拉選單完全不同。

4. **新增底部系統狀態列**：顯示即時 CPU / RAM 使用量。這個資料來源 `dashboard_stats.get_system_resources()` 其實 P1 就寫好了（用 `psutil`，專案本來就有在用這個套件），當時刻意沒接到畫面上，因為 P1 承諾「絕對不改變畫面」；這次是視覺改版，正好是接上它的時機，不算新增功能風險，只是把已經測過的資料接上畫面。讀不到（例如這台電腦沒裝 psutil）會顯示提示文字，不會讓程式當掉。

5. **順手修掉一個 P1/P2 就發現、但當時刻意不動的小地雷**：`import tkinter as tk` 原本只在 `if __name__ == "__main__":` 裡面才會執行，這次因為新的圓角卡片需要用到 `tk.Canvas`，已經沒辦法再靠這個技巧繞過去，所以把這行搬到檔案最上面的正式 import——這是一次乾淨的修正，不是新增風險。

## 怎麼驗證的

跟前幾輪一樣打樁測試，這次額外幫假的 Tkinter 環境補了 `Canvas`（記錄每次畫了什麼圖形/文字）跟 `ttkbootstrap.Style`（假的主題色盤）：

- 確認 4 張卡片都改成 Canvas，且各自畫出正確的「卡片底 + 圖示徽章」兩個圓角矩形，圖示徽章顏色正確對應到該模組的色系（綠/藍/黃/灰）。
- 模擬滑鼠移入卡片，確認底色真的重畫成更深的顏色；移開後確認恢復成原本的淡色調。
- 模擬點擊卡片（用「員工帳號管理」跟「營運狀態與尾隨監控」分別測），確認正確開啟對應視窗，跟改版前行為一致。
- 確認頂部時鐘在視窗一開就顯示真正的時間（不是預留的 `--:--:--`），底部系統狀態列一開就顯示真正的 CPU/RAM 數字（沒裝 psutil 的情況也另外測過，會安全顯示提示文字不會當掉）。
- 重跑 AI 代理設定＋RAG 啟動流程、QR 註冊視窗、關閉主視窗，確認這次風格改動沒有動到其他視窗的行為。

全部通過後，才把 `backend_main.py` 用你電腦上目前的修改時間當版本鎖寫回去，確認沒有覆蓋掉你電腦上更新過的版本。
