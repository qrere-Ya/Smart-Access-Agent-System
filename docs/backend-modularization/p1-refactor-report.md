## 怎麼驗證的

這台環境裝不了 ttkbootstrap/Tkinter 真正的視窗（沒有顯示器），所以驗證分兩層：

**`service_manager.py`（完全不依賴 Tkinter，可以直接測）**：實際開一個 socket 驗證 port 偵測、用假的行程物件驗證啟動/停止/存活判斷、驗證行程死掉時字典會自動清乾淨。特別做了一個端到端測試——真的呼叫 `start_rag_services_async()`，讓它依序嘗試啟動 Ollama（這個沙盒沒裝，正確落入警告分支）、LiteLLM（同樣沒裝，正確落入警告分支）、以及用真的 Python 直譯器去開一個不存在的 `app.py`（正確spawn 出行程、讀取到「檔案不存在」的錯誤輸出、偵測到行程以結束碼 2 死亡），確認整條「背景執行緒啟動→逐行讀輸出→偵測結束→回報結果」的鏈路完全正常運作。

**`dashboard_stats.py`**：對著真的 SQLite 資料庫測，塞入測試打卡紀錄後確認「不重複人數」「排序」「異常照片計數（只算 .jpg）」都正確；也測了資料庫連不上時安全回傳 `None`（不會讓畫面顯示假的「0 人」）。

**`console_panel.py` / `backend_main.py`（需要 Tkinter，用打樁測試）**：寫了一整套假的 Tkinter/ttkbootstrap/PIL/pyqrcode 元件，把 `backend_main.py` 整支檔案在假視窗環境裡「跑」過一遍——建立主視窗、開戰情儀表板、按人臉辨識開關、開員工資料庫、開 AI 代理設定並啟動 RAG（驗證有正確顯示結果訊息）、開 QR 註冊視窗（驗證連線失敗時安全顯示「伺服器準備中」而不是當機）、關閉主視窗，全部正常跑完沒有 AttributeError/NameError。過程中額外確認了一個**既有、不是這次造成的**小地方：`open_dashboard()` 裡 `self.count_var = tk.StringVar(...)` 依賴模組層級的 `tk` 這個名字，只有在直接執行 `python backend_main.py` 時（`if __name__ == "__main__":` 那段）才會綁定，正式使用時完全沒問題，但技術上是比較脆弱的寫法，之後 P3 質感細節清理時可以一併修正。
